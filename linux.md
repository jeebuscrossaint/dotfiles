# Linux

**Requirements:** GNU Stow, [coat](https://github.com/jeebuscrossaint/coat)

```sh
./install.sh          # stow -t ~ linux, then `coat apply`
stow -t ~ linux       # symlinks only, no theming
stow -D -t ~ linux    # uninstall
```

`linux/` is a single stow package: its tree mirrors `$HOME`, so
`linux/.config/foot/foot.ini` becomes `~/.config/foot/foot.ini`.

## Stack

| | | |
|---|---|---|
| compositor | **mango** | dwl-based, dwm tag model, runtime config with hot reload |
| compositor (stacking) | **labwc** | the floating/openbox-style alternative; see below |
| compositor (effects) | **wayfire** | stacking *with* animations, Exposé and Mission Control |
| bar | **waybar** | native modules + `mmsg watch` streamers for tags and title |
| notifications | **fnott** | also draws the volume/brightness OSD, via `~/.local/bin/osd` |
| launcher | **fuzzel** | .desktop entries with icons; `menu` / `menu-run` wrap it |
| lock / idle | **swaylock** + **swayidle** | |
| terminal | **foot** | |
| shell | **fish** | |
| editor | **nvim** | lazy.nvim |
| theming | **coat** | one command recolours every app below, live |

Start it from a TTY with `mango-run`, which raises the fd limit, validates the
config, keeps a log in `~/.local/state/mango/`, and wraps the session in a single
D-Bus bus.

## Three compositors

There are three, and they share everything below the compositor — same bar, locker,
notifier, launcher, screenshot and theme scripts:

| | tiling | stacking | stacking + effects |
|---|---|---|---|
| | **mango** | **labwc** | **wayfire** |
| start | `mango-run` | `labwc-run` | `wayfire-run` |
| config | `mango/config.conf` | `labwc/rc.xml` (+ `menu.xml`) | `wayfire.ini` |
| check | `mango -c <file> -p` | `labwc-check` | `wayfire-check` |
| reload | `mmsg dispatch reload_config` | `labwc -r` | automatic (watches the file) |
| model | 9 tags, 12 layouts | 10 desktops, everything floats | 3x3 workspace grid |

**wayfire** is the one with effects. labwc has no animations and no exposé — the words do
not appear anywhere in its config reference — so `scale` (Exposé, `W-e`), `expo` (Mission
Control, `` W-` ``) and the open/close/minimise animations are the whole reason it is
here. It also blanks the screen itself via `[idle] dpms_timeout`, which is why that
session runs swayidle with `config-wayfire`: lock only, no `wlopm`.

Its weak spot is decorations, the mirror image of labwc's. The buttons are already
circles, but they sit on the RIGHT with their glyphs always drawn, and the built-in
decorator has no option for which side they go on or for button images — so the macOS
traffic lights are a labwc-only thing for now. See `THIRD-PARTY.md`.

mango is the daily driver; labwc and wayfire are the stacking options. Binds are kept as
close as the three models allow, with sway's old config as the reference for all of
them. Where they can't match, the config file says why — labwc has no directional
window focus and no scratchpad, mango has no tabbed containers and no key-release
binds, and wayfire uses Linux input key names (`KEY_DOT`, not `period`) on a
workspace grid rather than a flat list.

labwc specifics worth knowing:

- `themerc` is generated by coat and gitignored — don't hand-edit it.
- `<decoration>server</decoration>`: real titlebars, macOS layout — traffic lights on
  the left, centred title. The root menu (right-click the desktop, `menu.xml`) is
  still there and is the mouse route to lock/exit.
- `W-f` maximizes (titlebar stays), `W-S-f` is true fullscreen.
- Snapping stands in for tiling: `W-S-<arrow>` half-screen, `C-A-<arrow>` grow to
  the neighbouring edge, `W-C-h/l/u/m` for the named regions in `rc.xml`.
- `xdg-desktop-portal/labwc-portals.conf` is required for screenshots and screen
  sharing: the wlr portal's own `UseIn=` list doesn't mention labwc.

## Layout

```
linux/
├── .config/
│   ├── coat/          scheme + module list; drives everything else
│   ├── mango/         tiling compositor: binds, layouts, monitors, autostart
│   ├── labwc/         stacking compositor: rc.xml, menu.xml, autostart, environment
│   ├── wayfire.ini    effects compositor: one file, all of it
│   ├── xdg-desktop-portal/  labwc-portals.conf (screenshots + screen share)
│   ├── waybar/        bar config + stylesheet
│   ├── fnott/         notifications and OSD
│   ├── fuzzel/        launcher (colours patched in place by coat)
│   ├── swayidle/      idle → lock → screen off
│   ├── swaylock/
│   ├── foot/  fish/  nvim/  bat/  btop/  zathura/  gtk-3.0/  gtk-4.0/  paru/
│   └── ...
└── .local/
    ├── bin/           session scripts — see below
    └── share/icons/   macOS cursor theme
```

Files coat *generates* (`coat-colors.conf`, `coat-colors.css`, `coat-theme.ini`,
the `themes/` dirs, `wmenu/coat-flags`) are gitignored. Only hand-written config
is tracked, so a scheme change never shows up as a diff.

## `.local/bin`

| | |
|---|---|
| `mango-run`, `labwc-run`, `wayfire-run` | start a session from a TTY |
| `labwc-check` | validate labwc's XML + check its Execute targets exist |
| `wayfire-check` | validate wayfire.ini against wayfire's own metadata |
| `audio-ensure` | repair the audio stack, but only when it is genuinely dead |
| `mango-tags`, `mango-title` | stream compositor state to waybar over `mmsg watch` |
| `waybar-fan`, `waybar-uptime` | the two things waybar has no module for |
| `menu`, `menu-run` | fuzzel wrappers — `menu` is dmenu mode for scripts, `menu-run` is the app launcher |
| `osd` | perform a volume/brightness/lock-key change *and* draw it as a notification |
| `theme-pick`, `theme-random` | coat scheme pickers |
| `swayscreenshot`, `swayscreenshot-edit` | region grab; `-edit` pipes to satty |
| `canvas-ical-fetch`, `canvas-ical-parse`, `canvas-notify` | Canvas assignment reminders |
| `prime-run` | run one app on the dGPU |
| `start-polkit`, `refresh-paru-completions` | session odds and ends |

## Retired

Kept here so nothing gets reintroduced by reflex. Every one of these was replaced
because it could not be recoloured live, or needed a supervisor process to
survive being recoloured:

**sway/swaybar** → mango/waybar · **dwl** → mango (compile-time config) ·
**tofi** → wmenu → **fuzzel** (tofi is not in OpenBSD ports; wmenu has no
.desktop support and no config file) · **gtklock** → swaylock ·
**dunst** → fnott · **swayrbar**, **slstatus**, **barstat** → native waybar
modules · **ashell** · **avizo**, **swayosd**, **wob** → the OSD is a
notification now · **kanshi** → mango's `monitorrule`

The reasoning for each is in the config file that replaced it, and the module
list at the top of `.config/coat/coat.yaml`.
